# ۳: خرابی CrashLoopBackOff کانتینر به دلیل بسته شدن پروسه اصلی (Exit 0)

## 📋 صورت مسئله و مشخصات سناریو
- **محیط اجرا:** ویندوز (محیط WSL / Docker)
- **شرح خرابی / تیکت پروداکشن:**
> **عنوان:** توقف آنی کانتینر پس از اجرا با کد خروجی 0 (Exited 0)
> **گزارش:** کانتینر اختصاصی پس از استارت بلافاصله متوقف می‌شود و امکان ارائه سرویس ندارد.

### 💥 اسکریپت شبیه‌سازی خرابی (Failure Injection)
```bash
docker run -d --name exiting_container ubuntu:latest bash -c "echo 'App Initialized' && exit 0"
```

---

## 🔍 گزارش عیب‌یابی و ریشه‌یابی (Troubleshooting)

* **مشکل (Problem):** توقف آنی کانتینر پس از اجرا با کد خروج صفر (`Exited 0`).
* **علائم بالینی (Symptoms):** کانتینر بلافاصله پس از ایجاد شدن خاموش می‌شود و فقط با `docker ps -a` قابل مشاهده است (وضعیت `Exited (0)`).
* **علت ریشه‌ای (Root Cause):** پروسه اصلی کانتینر (PID 1) یک دستور گذرا (`echo ... && exit 0`) بود که سریعاً به پایان رسید و هیچ پروسه پیش‌زمینه‌ای برای زنده نگه داشتن کانتینر وجود نداشت.

### 🛠️ مراحل رفع ایراد (Fix)

1. بررسی وضعیت کانتینر با `docker ps -a`.
2. بررسی آخرین خروجی با `docker logs exiting_container`.
3. اضافه کردن یک پروسه پیش‌زمینه پایدار (مانند `tail -f /dev/null` یا اجرای سرویس با فلگ `daemon off;`) در دستور اجرایی کانتینر تا PID 1 به‌صورت Foreground باقی بماند.

### 💡 درس‌آموخته مهندسی (Lesson Learned)

چرخه حیات (Lifecycle) هر کانتینر داکر مستقیماً وابسته به پروسه `PID 1` آن است؛ به محض پایان پروسه اصلی، داکر کل کانتینر را متوقف می‌کند.

---

### 🔄 اسکریپت بازگشت به حالت اول (Revert)

```bash
docker rm -f exiting_container || true
```
